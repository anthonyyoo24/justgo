## Candidate data handling

Settings → Account & data links to **Account** and **Data** without separate journal backup/recovery actions. Account contains Apple/Google login-method switches with provider logos and verified connection state, Log out and red Delete account. Linking/unlinking refreshes verified provider identities, preserves the owner and protects the final usable method. No View guest data row or separate signed-in status paragraph remains. Data contains iCloud Sync, matching down/up tray icons for Download my data and Import data, import preview/confirmation, and Delete all my data. Both deletion actions use the existing confirmation modal with distinct wording and retry state. Essential local history/account/data navigation is independent of fresh paid challenge admission; cloud operations still require authorization and connectivity.

Download uses the versioned `justgo-data` ZIP, containing the selected owner/kind, export time, complete captured accepted completion history and pending accepted completions, all current and preserved alternative journal entries with historical context, and requested Reduce Motion/Haptics preferences. It excludes credentials, sessions, raw queues, replication operations, aggregate rep/streak state and unsaved drafts. Signed-in download requires successful synchronization first; guest and signed-out downloads are phone snapshots, with signed-out cloud limitations disclosed. A file is readable and not app-password encrypted. Files/share destinations, including iCloud Drive, are user-controlled and separate from CloudKit and system backup.

Import validates bounded ZIP/schema/CRC/version/ownership/IDs/relationships/date/context before preview and explicit confirmation. Account files require the same authenticated owner; guest files may be remapped to the selected collection. Stable completion IDs reconcile without duplicate credit, existing differing journal versions remain preserved, and preference success requires durable readback. The file is not authentication. Validated imported records may be sent to the signed-in account or enabled iCloud copy. Supported older journal-only files are identified as partial backups. App-owned temporary files are removed after operation/cancellation/failure, before the next operation after interrupted processes and during owned deletion; user-saved copies remain external.

**Deletion:** Delete all my data removes the selected journal's saved completions/writing from the phone, signed-in JustGO cloud and previously associated app-managed iCloud copies while retaining account identity and login methods. Account-owned deletion requires sign-in; a guest journal with no associated cloud copy can be deleted locally/offline. Durable intent/epoch/generation handling supports retry and prevents stale automatic re-upload. Delete account additionally revokes sessions, closes the canonical owner, hard-deletes the managed Auth user through retryable server cleanup, permanently closes/purges associated iCloud account collections and clears matching phone credentials. Previously associated iCloud copies still require cleanup when Sync is OFF; unavailable associated Apple accounts leave cleanup durably pending rather than reporting success. Completed guest-source adoption cannot later resurrect the retired source. Neither action deletes the Apple/Google account or cancels a subscription. User-saved files remain; disconnected devices are not immediately erased. Retained minimal security ledgers must be applied before reopening an older restored database.

**Device protection:** OS-backed token storage and iOS Data Protection are the baseline, not evidence of a completed device audit. Verify actual SQLite/WAL/SHM and temporary-file protection, lock behavior, backup inclusion/exclusion, Keychain token failure/retry, Files save/pick/cancel/cleanup, Apple/Google native sign-in, CloudKit provisioning/account-change/conflict/quota/purge and relaunch on the signed iPhone. No additional app encryption or end-to-end encryption guarantee is made.
