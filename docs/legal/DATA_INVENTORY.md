## Implemented data handling

As of October 10, Settings → Export my data creates a ZIP on the current installation. It includes completed challenges, submitted feelings/reflections, safe account/device metadata, the current effective Reduce motion value and pending/rejected local copies. The owner selects an iOS share-sheet destination; the development browser downloads the file. The app does not automatically email or upload exports. Recovery/session secrets and internal diagnostics are excluded. Native temporary files are removed after sharing, cancellation or failure; an interrupted-process cache copy is removed before the next export. Keep physical-iPhone delivery and broader device/privacy acceptance open. See the [export handoff](../handoffs/phase-08-settings-privacy.md#october-10-data-export-implementation).

## Retention decisions for review

| Record                                | Starting position                                                        | Decision and evidence needed                                                                                                              |
| ------------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Personal journal                      | Keep while the account exists; remove through confirmed account deletion | Define completion deadline, all device/server copies, partial failure handling and user-visible pending cleanup.                          |
| Analytics events                      | Architecture proposes 90 days                                            | Owner approval and a matching PostHog configuration; not an existing guarantee.                                                           |
| Security records                      | Retain the minimum needed to reject revoked credentials and handle abuse | Review necessary fields, purpose and duration. Do not retain journal text as part of the security exception.                              |
| Database backups and operator exports | Bounded retention with restricted recovery access                        | Choose actual backup plan, expiry and deletion-restoration procedure. Account deletion must not be undone by restoring an older snapshot. |
| Support and suggestions               | Keep long enough to respond and manage the request                       | Choose inbox retention and deletion/request handling, including attachments people voluntarily send.                                      |
| Application and vendor logs           | Short, bounded operational retention                                     | Configure and disclose the actual periods, including hosting logs rather than only application serializers.                               |
| Billing and legally required records  | Separate necessary financial/security records from journal data          | Confirm legal duties, exact retained fields and vendor cleanup. App account deletion does not cancel an Apple subscription.               |

Provider backup defaults depend on the selected service plan and recovery configuration; they are not a JustGO retention decision. See [Supabase backup documentation](https://supabase.com/docs/guides/platform/backups).

## App Store disclosure worksheet

Use this as a review worksheet, not completed App Store Connect answers. Apple's definitions include functional data collection and partner SDKs, even when analytics is declined. [Apple App Privacy guidance](https://developer.apple.com/app-store/app-privacy-details/).

| Data                             | Categories to assess                                                                       | Purpose and linkage                                                                                                          |
| -------------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| Account and device identifiers   | User ID; Device ID where the final identifiers meet Apple's definition                     | App functionality/security; linked to the persistent account.                                                                |
| Uploaded challenge records       | Product Interaction and applicable user-content categories                                 | App functionality; linked. Analytics becomes an additional purpose only if enabled.                                          |
| Reflection text                  | Other User Content for generic free-form text                                              | App functionality; linked. Do not classify every possible topic a user could type as deliberately collected structured data. |
| Structured feeling response      | Review Health or other applicable categories against the app's actual purpose and question | Linked. Lack of HealthKit does not establish that this is not health data. Sensitive analytics requires separate review.     |
| Support emails and suggestions   | Customer Support, Email Address and any other fields actually requested                    | Support; evaluate the precise optional-disclosure conditions before excluding anything.                                      |
| Paid subscription data           | Purchases and applicable SDK identifiers                                                   | App functionality; linked when paid billing is active.                                                                       |
| Diagnostics and network metadata | Crash Data, Performance Data, Other Diagnostic Data and other applicable fields            | Final hosting/SDK settings determine the answer.                                                                             |

Review tracking against Apple's actual definition and every enabled vendor integration. Product analytics alone does not establish advertising tracking, but a vendor's independent use may change the answer. The final binary's privacy manifests and required-reason API declarations are separate release checks.
