## Implemented data handling

Settings → Export my data creates a ZIP on the current installation with CSV, JSON and a README. It includes completed challenges, submitted feelings/reflections, account/device metadata, the independent `analyticsRestricted` status, the current effective Reduce motion value, saved Haptics choice and pending/rejected local copies. It contains no legal acceptance/view receipt or acceptance-version metadata. The user selects an iOS share-sheet destination; the development browser downloads the file. The app does not automatically email or upload exports. Recovery/session secrets, unsaved input and internal diagnostics are excluded. Native temporary files are removed after sharing, cancellation or failure; an interrupted-process cache copy is removed before the next export. Online records are read in pages, not as an atomic cross-device snapshot. User-saved/shared copies follow the chosen destination's controls. Keep physical-iPhone export delivery and final signed-build acceptance open. See the [Phase 08 handoff](../handoffs/phase-08-settings-privacy.md).

Recovering an account on another phone restores uploaded history. It cannot restore another phone's only pending copy. Cloud authorization protects the journal from other app accounts; the journal is not end-to-end encrypted. Authorized operations and hosting providers can process stored content.

**Deletion and retained security records:** [Server deletion](../../apps/api/src/identity/delete-account.ts) removes activity/PATCH receipts, transfers, sessions and devices in one owner-locked transaction. The retained user row contains account ID, creation/deletion timestamps and the initiating session's digest. Revoked recovery rows retain credential ID, account ID, digest, kind and creation/revocation timestamps. These permanent security records contain no journal text, but remain identifiers/digests and are not anonymous. The [phone workflow](../../apps/mobile/src/app-support/identity/deletion/workflow.ts) saves confirmation of server deletion before clearing account-owned data and matching Keychain items; failed cleanup stays pending for retry. This product-safety confirmation is independent of legal acceptance and must remain. Server revocation does not guarantee immediate erasure of another offline phone, a user-created export or an OS backup. The [restore checklist](../operations/FOUNDATION.md#backup-restore-checklist) preserves deletion/revocation records when restoring an older snapshot.

**Device protection:** iOS automatically applies encrypted [Data Protection](https://support.apple.com/guide/security/data-protection-overview-secf6276da8a/web) to third-party app files. [AsyncStorage itself is an unencrypted key-value store](https://reactnative.dev/docs/security#async-storage); JustGO currently adds no Keychain-keyed journal vault. Installed AsyncStorage 2.2.0 attempts to exclude its directory from backup by default, with no project override found. Its actual file-protection class, backup exclusion and failure behavior require signed-build inspection; do not promise that OS backups include the journal. The native Keychain adapter uses `WhenUnlockedThisDeviceOnly` for device state and `WhenUnlocked` with synchronization for recovery credentials. The Phase 12 SEC-5 review retains this OS-backed baseline; no concrete gap currently establishes a need for a second vault. Actual signed-build file/backup verification remains in Phase 14, with remediation if a specific gap is found. No MMKV migration or added encryption was implemented.
