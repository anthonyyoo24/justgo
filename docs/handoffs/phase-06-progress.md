`GET /v1/progress?month=YYYY-MM&timeZone=<IANA zone>` returns account-level current/best streak and all-time reps, the requested month's reps, active days, daily counts and the viewer's current local date. `GET /v1/progress/days/:date?limit=20&cursor=…` returns the selected day's total reps and chronological entries with a bounded keyset cursor. Pages allow 1–50 entries. Both routes require an authenticated session and verified paid access; missing/invalid input, unpaid access and unavailable entitlement verification use the existing 400/401/403/503 boundary.

## Decisions and invariants

Current streak is the consecutive active-date run ending today or yesterday in the viewer's current time zone; best streak is the longest historical run. Reps count completed attempts, and active days count distinct frozen completion dates. Day entries sort by completion timestamp and attempt ID. The keyset cursor preserves PostgreSQL timestamp precision so equal-time or sub-millisecond completions do not skip or repeat entries. Mobile day queries fetch 20 entries per page and concatenate pages; account Progress is invalidated after confirmed completion, finalized reflections and screen focus.

## Setup, data and operations

- Use the existing identity, database and local development entitlement configuration from the earlier handoffs. Progress introduces no new secret or environment variable.
- Apply migrations in journal order through `0009_drop_attempt_elapsed_seconds.sql`. Migration 0008 adds the history index; migration 0009 drops `elapsed_seconds` and replaces the attempt outcome constraint without rewriting completion dates or reflections.
- Coordinate migration 0009 with the API and mobile contracts. An older API still writes the dropped column, and older mobile contracts require `elapsedSeconds`; the current strict contract also rejects that field from an older API. Do not assume mixed-version compatibility. Before staged rollout, plan a coordinated cutover or explicitly implement and test a compatibility bridge in its own work. Prefer a forward repair; reverting only the API/UI cannot restore the dropped column or its values.
- Local setup/check commands remain `npm run db:local`, `npm run db:migrate`, `npm run check` and `npm run test:db`. Start the isolated test API with `npm run dev:challenges -w @justgo/api` and the mobile web preview with `npm run dev:web`. `/preview` is development-only; `progressState=loading|empty|error` and `progressDayState=initial-error|load-more-error|loading-more` select presentation fixtures.
- Progress reads require verified paid access. The challenge development entrypoint remains an isolated local test fixture; production access stays closed until phase 07 billing verification exists.
- The month response contains counts only. Submitted reflection text is returned solely in owner-scoped day history. Keep private text out of logs, analytics and handoff fixtures.
