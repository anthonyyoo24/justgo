## Decisions and invariants

- Browsing/venue order/unfinished activity are process memory. A fresh controller/launch resets them. Start captures the original timestamp/time zone and an absolute five-minute deadline; countdown rendering samples that deadline rather than extending it on foreground. Give-up creates no saved attempt.
- Completed allocates one attempt UUID and retains it through an interrupted save. Once submission starts, Give-up cannot turn accepted completion into abandonment. Repository storage/network fallback owns saving; its ordinary durable phone write does not await cloud confirmation.
- Reflection writes occur only on explicit Save, including dirty-close Save. Empty Skip and clean Close write nothing. Nonblank whitespace and the original feeling are preserved according to shared contracts. Newer typed input during saving prevents late navigation; account changes/unmount fence callbacks.
- The root warning uses known connectivity/storage causes only. An HTTP outage is not described as offline. Memory-only activity is never called saved. Dismissal leaves retained content/retries intact. The shell observes monotonically increasing recovery sequences, routes to the current host and dismisses old-account feedback; sheets cannot emit a second toast.
- Cause-specific intervention lives in the saving notice, without a generic Progress Sync status or placeholder support destination. Auth opens existing account recovery; invalid reflection requests expose retained writing for an explicit changed submission. The typed error supplies no field-specific explanation, so the UI does not invent one. Coverage/time/missing-record/permanent request failures retain content with truthful diagnostics and no endless unchanged retry.
- Genuine reflection revision conflicts use 07.2 backend-wins reconciliation. Untouched editor state adopts it automatically; there is no attention link or chooser. Dirty unsent input remains editable.
- Existing access freshness/expiry behavior is preserved. Short offline web cases run within that access window; they do not establish billing/offline-access policy beyond it. 07A owns verified provider coverage.
- A new valid session waits for the account’s journal hydration and active foreground before clearing auth-blocked uploads. A deferred callback cannot resume another account or a disposed runtime.
